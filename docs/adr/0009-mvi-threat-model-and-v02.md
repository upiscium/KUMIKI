# ADR-0009: MVI の脅威モデルを 2 段にし、KAGARI v0.2 系を MVI で出す

- **Status:** Accepted（2026-11-13、User 判断）
- **Human decision:** 脅威モデルは案A。v0.1 系の資産の扱いは現状（ADR-0008 D2）を維持する。次のリリースは MVI を v0.2 系とする（2026-11-13）。
- **Issue:** #420
- **Related:** ADR-0001（#1、#6）、ADR-0003（原則 3）、ADR-0006（D8）、ADR-0007（D3、D4、D7）、ADR-0008（D1、D2、D4）
- **Amends:** ADR-0001 #1（守る範囲に「外部からの入力による誘導」を加える）。ADR-0008 D1 で保留にした ADR-0006 D8 のリリース定義を、この ADR で置き換える

## Context
- ADR-0001 #1 は、守る範囲を「通常のミスや意図しない変更」に限っていた。悪意ある Agent への頑強性は保証しない、と明記している。
- MVI（ADR-0007）では、public リポジトリの Issue 本文が Claude に渡りうる（D4）。独立レビューの指摘に対応するうちに、agent が意図的に仕掛ける前提の対策が積み上がった。例として、runner 側での commit、テスト結果のすり替え対策、レビュアーの起動の乗っ取りの記録がある。ただし、どこまでを守る範囲にするかは決めないままだった。そのため、ADR-0003 原則 3（障害のたびに関門を増やさない）と食い違い始めていた。

## Decision

### D1 — 脅威モデルを 2 段にする（案A）
1. **基本**：ADR-0001 #1 と同じく、通常のミスと意図しない変更から守る。
2. **追加**：外部から渡る入力による誘導から守る。外部からの入力とは、第三者が書いた Issue の本文やコメント、対象リポジトリの内容、依存パッケージを指す。具体的には、誘導された agent が次のことをしないようにする。
   - GitHub の資格情報に届くこと
   - Contract の範囲の外を操作すること
   - 人間の判断が要る操作を行うこと
3. **範囲外**：agent が自ら悪意を持って仕掛ける場合への完全な防御は、守る範囲に含めない。例として、テスト結果のすり替え、記録の改ざん、レビュアーの起動の乗っ取りがある。root やホストの侵害も範囲外とする。
4. **すでにある対策の扱い**：3 にあたる対策で、すでに実装したものは残す（ADR-0007 D7、#418）。ただし、この種の対策を新しく足すことはしない。新しい指摘は、既知の限界として記録するにとどめる。

**判断の基準**：新しい対策を足すかどうかは、「2 の誘導によって、資格情報・Contract の範囲の外・人間の判断が要る操作のどれかに届くか」で決める。届かないものは、ADR-0001 #6 に従って足さない。

### D2 — v0.1 系の資産の扱い
- ADR-0008 D2 を維持する。Evidence、Recovery、metadata、dispatch 経路の部品は、必要が示されたときだけ取り込む。

### D3 — KAGARI v0.2 系は MVI で出す
- 次のリリースは、`components/kagari-mvi/` を中心とする KAGARI v0.2 系とする。ADR-0006 D8（v1 dispatch 経路を使うリリース）は採用しない。
- ADR-0006 の D6（同時実行数を 2 に上げる条件）と D7-3（v3 からの移行を始める条件）は、v0.2 系では扱わない。必要になった時点で、改めて決める。
- **v0.2.0 の条件（たたき台、User の確認待ち）**：
  - ADR-0008 D4 の前提条件を満たしていること（Contract 権限窓口 #418、GitHub Actions の secrets への対策、レビュアーの起動の乗っ取りへの対策の判断、dispatch 経路を削除するかの判断）
  - レビューを OpenCode と TSUMGI に切り替える選択肢があること（ADR-0007 D6 の 2 周目）
  - KUMIKI 自身を対象にして、E2E を一周させること
  - systemd timer で動かす手順が README にあること
- タグの作成とリリースは、ADR-0001 に従って User が行う。

本 ADR は、Merge、Release、本番適用を承認するものではない。
